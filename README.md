# FRP broadcasting — Scoreboard Controller

Windows WPF (.NET 10) app for streaming padel tournaments of the **Federația Română de Padel (FRP)** with OBS: live scorebug, players intro, court TV, instant replay, commercial breaks and an announcements bar, with the players imported from padeltour.ro. It started as the production tool of FIP Gold Bucharest 2026 (a fork of [PadelTool](https://github.com/RaulNo7/PadelTool)). Branding: the FRP logo (`Scoreboard\public\frp-*.png`, `app.ico`) and the Romanian flag colours — blue `#002B7F`, yellow `#FCD116`, red `#CE1126` — on the app screens and on every stream graphic, with a blue-yellow-red stripe under the headers and along the scorebug, intro and info bar. Internal names stay as they were (exe `FipGoldBucharest.exe`, data folder `%AppData%\FipGoldBucharest`, repository) so existing settings, match state and OBS sources keep working.

## What it does

- Hosts the bundled Node.js score server (`Scoreboard\server.js`) as a hidden child process.
- **Home tab** — embeds the referee remote (`/mobile`): scoring, undo/redo, manual adjust, and per-player serve selection. On a phone the referee page keeps the screen on while it is open (Screen Wake Lock on the https tunnel link; on the plain-http venue link a tiny silent looping video does the same); the "☀ screen on" chip in its header shows the state — if it says "tap to keep screen on", tap once.
- **Score settings tab** — the control panel (`/admin`): pick the two teams of the current match from the official entry lists, overlay display options, reset.
- **Teams tab** — the roster, one card per division (e.g. Masculin 1, Masculin 2, Feminin 1, each with its accepted pairs and waiting list; the older entry list shows Men / Women) with an Active/Eliminated toggle per team; eliminated teams cannot be picked for a match. Player names and country codes (2-letter, e.g. RO, or the older 3-letter FIP codes) can be corrected in place (click a name or ✎, or click the code; Enter saves, ↺ restores the imported data); the correction follows everywhere, including a match already in progress, and survives restarts. The pair that loses a match is eliminated automatically when the match finishes (reinstated if the result is undone).
- **OBS overlay** (`/overlay`, Browser Source 1920×1080, transparent) — 4 player rows with country flags, serving-player dot, blue completed-set columns, gold current-set games, white points.
- **Court TV display** (`/tv`) — the same scorebug filling the whole screen on a black background, for a TV/laptop/tablet at the court (URL with the LAN address is in the admin panel). It keeps showing the final score during commercial breaks.
- **Players intro** (`/intro`) — a transparent second OBS Browser Source showing the tournament header and the four players with big flags over the court video, toggled with the **Show players** button (Media tab); it hides automatically when the match starts and can show the scheduled start time (Score settings → Match start time).
- **Replay cover** (`/overlay?pos=…&cover=1`) — OBS's replay buffer records the program picture, so the **score is baked into every replay clip**. In cover mode the scorebug page lays out the very same scorebug (same size, same position) but covers its rows with an opaque blue/gold "REPLAY" plate, and shows only while a replay clip is on the stream. Put it in the `REPLAY` scene as a duplicate of the LIVE scene's scorebug source (same size and transform) and the score disappears from replays; `&preview=1` keeps it visible while lining it up.
- **Admin tab** (app-only page `/settings`, never served on the public port) — first card **Import players** (see below); every card can be collapsed to its title by clicking the title bar (all collapsed by default; a card you open or close is remembered per card on that PC). OBS overlay/intro URLs, the **Info bar** card (bottom-bar settings and its local/outside URLs), court TV URL, the YouTube live-stream link, the tunnel hostname, the access key and all public links, plus a **Score server** card (status, Start/Stop, port, auto start, minimize to tray, LAN overlay/referee URLs) that drives the desktop app through the WebView2 message bridge — it appears only inside the app. While the server is stopped the tab shows a placeholder with a Start button and the port.
- **Home page** (`/`, public) — FRP broadcasting start page with a menu to all pages (Scorebug, Court TV, **YouTube Live** while a stream link is saved on the Admin tab, and — with the access key — Referee, Score settings, Teams, Media, Announcements). The hero tag shows the imported tournament, a **Tournament** tile links to its padeltour.ro page, and the live score is shown below. Opening the page with `?key=…` stores the key for the control links.
- **Scorebug page** (`/scorebug`, public) — preview of the live widget, the fixed HTTPS link and an HTML `<iframe>` snippet (position / scale / size) to embed the scorebug on any website; the Scorebug menu entry and card open this page (the raw overlay stays at `/overlay`).
- **Media tab** — the broadcast controls (OBS status, Show/hide players, Show/hide score, Play commercials, Cancel), an **instant replay** card (a **Replay** button saves the last N seconds from OBS's replay buffer — length configurable, default 20 s — into the `Replay\` folder — titled with the players, the score and the date, e.g. `Ion Popa_Dan Marin vs Ana Rusu_Luis Vega 6-4 2-1 (30-15) 12-11-2026 14꞉05.mp4` (the time uses the look-alike colon `꞉`, U+A789, because Windows does not allow `:` in file names; the Media tab shows it as `:`) — and plays the clip at once on the replay scene; a dropdown keeps the last 10 clips with a **Play** button, to show the best points again during a pause, and a red **Cancel** next to it stops the clip and goes back to the live scene; the scorebug is hidden for the whole replay and restored afterwards if it was showing; the app keeps OBS's replay buffer running), plus a dropdown of every video file in the **Commercials folder** (by default the app's own `Commercials\` directory, changeable in the settings card) with a **Play** button. Playing a video temporarily swaps the file of the OBS media source, plays through the same break routine and restores the merged break video afterwards; the last file played is shown in the card. The Play-all / automatic break uses the spot list in `obs-settings.json` (`01_FIP_INTRO.mp4` … `06_MONDO.mov`, looked up by name in the same folder). After a single spot the score always comes back (spots are for during the game); after "Play all" / the automatic break it comes back only if a live match was interrupted, and stays hidden after a finished match.
- **Announcements tab** (`/announcements`, between Media and Teams) — add, edit, switch on/off, reorder and delete the texts of the bottom bar. Each announcement is either **Always on** (stays until you switch it off) or on a **Timer** (on for N minutes or hours, counted from the moment it is switched on, then it switches itself off; switching it on again restarts the countdown). The bar's own settings — show/hide, seconds per announcement (default 8), the label on the left (default `INFO`) — and its OBS links (local and from outside) are in the **Info bar** card on the Admin tab. Stored in `%AppData%\FipGoldBucharest\announcements.json`, so "Reset everything" never touches them. Over the tunnel it needs the access key, like the other operator pages.
- **Announcements bar** (`/ticker`) — a transparent full-canvas Browser Source with an opaque bar along the bottom edge that shows the announcements that are on air **one after another, in a loop**; a text too long for the bar scrolls through once during its turn, and dots on the right show which one of how many is showing. It slides away when nothing is on air or the bar is switched off. `?scale=0.9` for a thinner bar, `?preview=1` shows a sample text while you position it. Also served on the public port.
- **Commercial breaks** — a configurable delay (default 60s) after a match ends: the scorebug fades off the stream, OBS switches to the commercials scene, the six spots are loaded into its media source **one after another** (no merged file needed; a "single merged file" mode remains available in the settings), and OBS returns to the live scene when the last one ends. The score stays hidden while the next match is set up and reappears when it starts. A "Play commercials now" button runs the same break manually; countdown + Cancel are shown in the admin panel.

## Import players from padeltour.ro

Admin tab → **Import players**:

1. Paste the tournament link, e.g. `https://www.padeltour.ro/turnee/padel-palace/padel-palace-major/nov2026?tab=inscrisi`, and press **Load categories**. The categories of the tournament appear; **Masculin 1, Masculin 2 and Feminin 1** are ticked by default.
2. Choose whether to include the **waiting list** (on by default — those pairs are listed under "Waiting list" so a late replacement can be picked), then **Read players**. A table shows per category how many pairs the site lists, how many were read (accepted / waiting list) and any notes (players without a country, entries without a partner).
3. The app then asks **every time**: **Keep** the current teams and add the new pairs (pairs already in the same division are skipped), **Replace** them (the eliminations and name/country corrections are cleared too), or **Cancel** (nothing changes).

How it reads the site: padeltour.ro loads its registrations list in the browser after the page opens, so a plain download does not contain the pairs. The app takes the categories from the page itself and opens each category (`&cat=<id>`) in a hidden **Microsoft Edge** (headless, driven over its DevTools interface), waits until the list has loaded and stopped changing, checks that the page shows the requested category (its "22+2 Wildcard-uri" capacity), and reads the pairs: names, the PT points of each player and of the pair, wildcard and waiting-list marks, and the country from the flag shown next to each name (🇷🇴 → `RO`). Players without a flag get an empty country. Three categories take about 5 seconds. Only `https://(www.)padeltour.ro/turnee/...` links are accepted, and the import is never reachable through the internet tunnel.

**Paste fallback** (no internet, Edge missing, or the site changed): open the category on padeltour.ro, Ctrl+A, Ctrl+C, and paste it in "Paste the list instead" with the division name — same reading code, same Keep/Replace question.

If padeltour.ro changes its page layout the reader may need an update (`Scoreboard\src\padeltour.js`, tests in `test/padeltour.test.js`). For a long-term source, ask the organiser or padeltour.ro for an export.

## Match format

- Best of 3 sets, 6 games per set, tiebreak at 6-6 to 7 points, win by 2.
- **Deuce rule** (Score settings → Match format): **Star point** (default — advantage at the first two deuces, the third deuce is a single decisive point, shown as `SP`), **Golden point** (no advantage: the point at 40-40 wins the game, shown as `GP`) or **Killer point** (one advantage deuce `D1`, then the next deuce is the decisive point, shown as `KP`).
- **3rd set** (same card): a **normal set** (default) or a **maxi tiebreak to 10**, win by 2, played instead of the deciding set (shown as 7-6 / 6-7 with the tiebreak points, like a set won on a tiebreak). Choose it before the match starts — a deciding set already under way is not converted.

## Data

- `%AppData%\FipGoldBucharest\roster.json` — the roster imported on the Admin tab (it wins over the bundled list). `Scoreboard\data\teams.json` — the entry list bundled with the app (the 8 FIP Gold Bucharest 2026 semifinalist pairs), used until the first import.
- `Scoreboard\public\flags\*.svg` — every 2-letter country flag (257, from the MIT-licensed [flag-icons](https://github.com/lipis/flag-icons) set 7.6.0, licence next to them), so the overlay works offline.
- Settings: `%AppData%\FipGoldBucharest\settings.json` · live match state: `%AppData%\FipGoldBucharest\scoreboard-state.json`.

## OBS setup for the commercial break

1. **Tools → WebSocket Server Settings** → Enable, note the port (default 4455) and password.
2. Create a scene named `COMMERCIALS` containing one **Media Source** named `Commercials` (any video file — the app loads each spot into it), with **"Restart playback when source becomes active"** ticked. The app also fits the source to the canvas before every break, so spots of any resolution display correctly.
3. In the app's **Admin** tab → **Commercial break settings** card (after Info bar): enter the WebSocket URL/password and the scene/source names, press **Test connection** (the result shows under the buttons), then **Save settings**.
4. For the instant replay: **Settings → Output → Recording → enable "Replay Buffer"** (the app sets its length and starts it), and create a scene named `REPLAY` containing one **Media Source** named `Replay` (any file; "Restart playback when source becomes active" ticked). Each saved clip is moved from OBS's recording folder into `Replay\` (folder, scene and source names are configurable in the Media tab's settings card). Add the **replay cover** (URL in the Admin tab's "OBS overlay URL" card) to the same scene as a duplicate of the LIVE scene's scorebug source — same size, same transform, above the media source — so the score baked into the clip is covered by a "REPLAY" plate; a Stinger/Swipe **Transition Override** on the scene (right-click → Transition Override) marks the change even more clearly.
5. For the announcements bar: add `/ticker` (URL in the Admin tab's Info bar card) as a **Browser Source** in the `LIVE` scene, sized **exactly like the canvas** (1920 × 1080), above the other sources. The replay buffer records the bar into replay clips too; since the bar is opaque, a copy of the same source in the `REPLAY` scene (Paste (Duplicate), same transform) covers the recorded one with the live bar.
6. For the players intro: add `/intro` (URL in the "OBS overlay URL" card) as a **second Browser Source** in the LIVE scene, above the camera, sized **exactly like the OBS canvas** (Settings → Video → Base resolution, e.g. 1920×1080 or 1280×720), then reset its transform (Ctrl+R). The card centers itself and scales with the source; `?scale=0.8` makes it smaller.

Settings are stored server-side in `%AppData%\FipGoldBucharest\obs-settings.json` (never broadcast to referee phones). If OBS is unreachable, scoring keeps working and the error is shown in the card.

## Public HTTPS URL (internet tunnel, fixed address)

The score server also listens on a **read-only port** (main port + 1, i.e. **8081** by default; `PUBLIC_PORT` env to change, `0` to disable). It serves only `/overlay`, `/tv`, `/intro`, their assets, `GET /api/state` and a broadcast-only WebSocket — no control pages, no commands, no settings. Expose **only this port** to the internet through a tunnel with a fixed hostname:

- **Cloudflare Tunnel** (recommended; needs a domain on a free Cloudflare account): Zero Trust → Networks → Tunnels → *Create a tunnel* → install `cloudflared` on the streaming PC as a Windows service (the one-line command shown with the tunnel token) → *Public Hostname*: `scorebug.yourdomain.com` → Service `http://localhost:8081`.
- **Tailscale Funnel** (no domain needed): install Tailscale on the streaming PC, enable Funnel for the tailnet, then `tailscale funnel 8081` → public `https://<pc>.<tailnet>.ts.net`.

The URL to give FIP is then `https://<hostname>/overlay?pos=top-left` (top-left is also the default without `?pos=`; add `&scale=` if they need it). The **court TV** page is public on the same hostname (`https://<hostname>/tv`). The **referee, admin, teams and media pages** are available there too, but only with an **access key**: set the hostname and a key in the admin panel's *Internet access (tunnel)* card (Generate → Save); it then shows the links `https://<hostname>/mobile?key=…`, `/admin?key=…`, `/teams?key=…` and `/media?key=…` — the whole app can be operated remotely. The key unlocks those pages, their APIs and score commands over the public port (opening a page once with `?key=` stores it in a 30-day cookie); without it the internet only sees the scorebug and court TV. Leave the key empty to keep the operator pages LAN-only. It works over HTTPS/WSS as-is and stays the same all week regardless of the venue LAN IP. Keep the PC on a wired connection, the app on auto-start, and the tunnel installed as a service so it survives reboots; test the public URL from a phone on mobile data before the first match.

## Running

Requires Node.js on PATH (or set its path in settings). Build & run:

```
dotnet run --project FipGoldBucharest.csproj
```

**Windows Smart App Control**: on a PC where Smart App Control is on (Windows Security → App & browser control), double-clicking `FipGoldBucharest.exe` is blocked because a locally built exe is unsigned ("did not meet the Enterprise signing level requirements" in the CodeIntegrity log). Start the app through the Microsoft-signed host instead — `dotnet run`, or `dotnet bin\Debug\net10.0-windows\FipGoldBucharest.dll`, or a shortcut whose target is `"C:\Program Files\dotnet\dotnet.exe"` with that dll as argument (Run: Minimized hides the console window). **This only works for a `FipGoldBucharest.dll` that Smart App Control already accepts**: on the operator PC that is the build of the current C# sources (builds are deterministic, so rebuilding unchanged C# code reproduces the same accepted file). Any change to the C# code (`*.cs`, `*.xaml`, the csproj) produces a new, unknown DLL that is blocked with "An Application Control policy has blocked this file (0x800711C7)" — then either revert the C# change and rebuild, sign the binaries with a certificate Windows trusts, or turn Smart App Control off. Changes under `Scoreboard\` (the Node server and the pages, where almost all features live) are not affected. **Update 4 October 2026**: no block has been logged on the operator PC since 1 October although Smart App Control is still on, the unsigned exe starts normally, and a build with the new Announcements tab loaded without a block in a probe; the last working build is kept in `bin\accepted-build-backup\` — if a new build is ever blocked again, copy those three files back into `bin\Debug\net10.0-windows\`. Without the desktop app the score server also runs on its own: `node Scoreboard\server.js` with `PORT=8080` and `STATE_FILE=%AppData%\FipGoldBucharest\scoreboard-state.json`, then open `http://127.0.0.1:8080/` in a browser.

The referee opens the phone URL shown at the bottom of the Admin tab (same Wi-Fi network). Add the overlay URL from the Admin tab as an OBS Browser Source.

Scoring-engine tests: `cd Scoreboard && npm test`.
